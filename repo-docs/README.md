维护者更新作品元数据和文字层后，希望发布一个浏览器能直接打开的阅读站。这里沿静态构建解释数据怎样进入页面，以及为什么页面、检索库和发布清单必须来自同一次构建。

## 覆盖范围

覆盖构建命令编排、清单与检索库交接、站点生成和预算守卫；源码地图只列这条路径涉及的文件。浏览器阅读偏好、备份恢复、在线检索细节、OCR 导入与三平台真实部署未展开。未提交的阅读器及外观变更保持原样，不作为已发布事实。

本包采用 Lite 加代码地图：主流程先建立行为模型，地图用于定位，证据页用于审计。源码和脚本是实现事实的依据；旧文档或测试文件的存在不代表本轮实跑通过。

## 运行与验证入口

以下命令在仓库根运行；启动命令会占用开发端口，构建命令可能写业务产物，请先阅读根规则。

```sh
npm ci
# 以下会生成业务构建产物，先确认自己的预览输出可替换
npm run build
# 维护者验收命令，本轮未运行
npm run check
npm test
```

文档站的启动与构建命令见根 README 的文档入口。文档构建只验证说明页面，不证明业务可用或已部署。
