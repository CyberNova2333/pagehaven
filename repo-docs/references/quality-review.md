# 页间 · Pagehaven 文档质量复核

这是审核记录，用于检查指南是否给出可复述的行为模型，以及尚未覆盖的风险。

## Reader Simulation

| 读者问题 | 从指南能得到的答案 |
| --- | --- |
| 从哪里进入，看到什么输出？ | walkthrough 的代表性输入表和编号步骤给出入口、交接和结果。 |
| 难点是什么？ | 维护者更新作品元数据和文字层后，希望发布一个浏览器能直接打开的阅读站。这里沿静态构建解释数据怎样进入页面，以及为什么页面、检索库和发布清单必须来自同一次构建。 |
| 分成哪些阶段？ | 固定构建输入 → 绑定检索库版本 → 生成章节页面 → 补齐静态文件 → 校验预算 → 核对部署回执并条件启用版本。 |
| 失败边界在哪里？ | 代表性 case 同时列出成功与拒绝/恢复分支；源码定位可用于反查。 |
| 怎样验证？ | walkthrough 末尾给出命令，change-log 保存实际结果；源码检查、测试执行、构建和部署分别记账。 |
| 为什么同一产物不能无条件发布四端？ | ESA 的 2,000 文件预算中预留一个部署验证文件，业务产物最多 1,999 文件；`all` 必须满足所有目标的限制，GitHub 目前也没有独立预览环境。 |
| 命令成功是否代表上线？ | Workers 与 ESA 必须读回只交给本次目标的随机验证文件；其他平台或上次部署的标记不能产生成功回执。ESA staging 使用同一包的请求和连接器。实际云端验收仍需另行执行，详见 walkthrough 的 Step 6。 |

## 可理解性与剩余风险

先讲可观察行为，再提供源码位置；代码地图只用于找职责，证据表不承担主解释。代表性 case 来自已读分支，不伪造真实请求结果。

反证检查（Falsifying check）：若不匹配的内容仍能进入已绑定数据库的页面，或关闭平台配置后站点依赖函数才能阅读，当前静态构建模型需要修订。

后续问题（Next reader question）：浏览器如何按块读取检索库？packages/search 与 core/chunkfetch 暂缓展开；总体约束见原架构文档。

覆盖构建命令编排、清单与检索库交接、站点生成、目标预算及部署回执边界；另记录配色控件与主题变量的兼容接线。其余浏览器阅读偏好、备份恢复、在线检索细节、OCR 导入与平台真实部署验收未展开。当前工作区实现不等于已发布版本。

需要复核具体声明时，回到[两遍调查记录](source-evidence.md)；验证结果的适用范围见[指南同步记录](../change-log.md)。
